## changes
Highlights

JavaScript parsing with SWC Next

Rspack now uses <a href="https://github.com/swc-project/swc-next">SWC Next</a> for JavaScript parsing. This beta also includes follow-up compatibility fixes for block-scoped functions, parser source types, and legacy parser behavior. See <a href="https://github.com/web-infra-dev/rspack/pull/16089" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/16089/hovercard">#16089</a>.

Content-based loader filtering

The new loader <a href="https://rspack.rs/config/module-rules#rulesusefiltercode" rel="nofollow"><code>filter.code</code></a> option accepts a string or regular expression and checks the loader's current input before running its normal transform. Loaders can skip files that do not contain the syntax or markers they need to process, avoiding unnecessary transformation work. For example, a loader that transforms <code>customMacro()</code> calls can use <code>filter: { code: 'customMacro(' }</code> to skip inputs without that marker. Pitch functions are unaffected. See <a href="https://github.com/web-infra-dev/rspack/pull/16073" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/16073/hovercard">#16073</a>.

Better SplitChunks output

Named cache groups now remove redundant module copies from source chunks connected to the same shared chunk, reducing duplicate code in affected builds. Rspack also supports <a href="https://rspack.rs/plugins/split-chunks-plugin#splitchunksminremainingsize" rel="nofollow"><code>splitChunks.minRemainingSize</code></a> to avoid splits that leave undersized chunks, bringing JavaScript and extracted CSS output closer to webpack. For example, an affected asynchronous CSS import now retains its expected <code>controls.css</code> filename in production. See <a href="https://github.com/web-infra-dev/rspack/pull/16075" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/16075/hovercard">#16075</a> and <a href="https://github.com/web-infra-dev/rspack/pull/15594" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/15594/hovercard">#15594</a>.

Better watcher compatibility

Native and Node watch file systems now expose watchpack-compatible <code>getTimes()</code>, <code>getTimeInfoEntries()</code>, and <code>collectTimeInfoEntries()</code> APIs. With <a href="https://rspack.rs/config/experiments#experimentsnativewatcher" rel="nofollow"><code>experiments.nativeWatcher</code></a>, <code>compiler.fileTimestamps</code>, <code>compiler.contextTimestamps</code>, and the watcher's <code>getInfo()</code> now return real timestamp entries, improving compatibility with plugins that rely on watch metadata, such as <code>ts-loader</code>, <code>webpack-virtual-modules</code>, and <code>vue-loader</code>. The Node watcher also merges time-info entries deterministically so directory timestamps are preserved regardless of dependency iteration order. See the <a href="https://rspack.rs/types/watch-file-system" rel="nofollow">WatchFileSystem API documentation</a>, <a href="https://github.com/web-infra-dev/rspack/pull/15754" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/15754/hovercard">#15754</a> and <a href="https://github.com/web-infra-dev/rspack/pull/16126" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/16126/hovercard">#16126</a>.

Memory improvements and diagnostics

Rspack avoids retaining serialized source maps, reducing memory retained by source objects. Source handling also uses a source-wide UTF-16 index and removes its object pool. See <a href="https://github.com/web-infra-dev/rspack/pull/16072" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/16072/hovercard">#16072</a> and <a href="https://github.com/web-infra-dev/rspack/pull/16083" data-hovercard-type="pull_request" data-hovercard-url="/web-infra-dev/rspack/pull/16083/hovercard">#16083</a>.

New allocative-based memory diagnostics help identify which Rust data structures retain memory during builds and HMR updates. See the <a href="https://rspack.rs/guide/diagnostics/memory" rel="nofollow">memory diagnostics guide</a> to capture and analyze snapshots.
