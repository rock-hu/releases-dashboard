# v2.2.0-beta.1

## release on 20260818
## description
## changes
Highlights

RSC: Client Component CSS now uses Flight preinit

Rspack now emits Client Component exports as registered client references directly. CSS imported by a Client Component is no longer injected by wrapping its exports with generated <code>&lt;link&gt;</code> elements; the stylesheet is preinitialized from the React Flight payload instead. This preserves client-reference identity, including default, named, CommonJS, and non-component exports. Explicit link generation remains available through <code>import.meta.rspackRsc.loadCss()</code>.

This is a breaking change for RSC framework integrations. Upgrade <code>react-server-dom-rspack</code> to <code>0.1.0</code> and update any code that relies on the previous export-wrapper behavior.

SWC 77: Wasm plugins must be rebuilt

<code>swc_core</code> is upgraded from 76 to 77, which changes the serialized AST encoding across the SWC Wasm plugin boundary. Plugins compiled against an earlier SWC schema no longer load and the build fails with <code>The version of the SWC Wasm plugin you're using might not be compatible with 'builtin:swc-loader'</code>. Rebuild your plugin, or upgrade to an SWC 77 compatible release .

Use <a href="https://plugins.swc.rs/" rel="nofollow">plugins.swc.rs</a> to find the plugin version matching your Rspack release, and see <a href="https://rspack.rs/errors/swc-plugin-version" rel="nofollow">SWC plugin version mismatch</a> for details. SWC 77 also introduces dedicated <code>FunctionBody</code> and <code>ArrowFunctionBody::FunctionBody</code> AST nodes, a breaking change for Rust-side consumers of the SWC AST.

CSS Modules: standards-aligned Unicode identifiers

CSS identifier escaping and unescaping now follow the CSS Syntax standard, so Unicode identifiers are emitted directly instead of carrying unnecessary backslashes.

    .😍 {
      color: red;
    }

now generates <code>.style_modules_css-😍</code> rather than <code>.style_modules_css-\😍</code>.

CSS Modules coverage also expands to more webpack cases — local/global modes, generator options, ICSS <code>@value</code>, custom identifiers, and warning order — and dependency collection moves into <code>css-module-lexer</code>, so stylesheets are no longer rescanned with regular expressions after parsing.
