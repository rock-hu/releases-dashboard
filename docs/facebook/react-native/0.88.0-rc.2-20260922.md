# 0.88.0-rc.2

## release on 20260922
## description
## changes
Changed

* <strong>Metro</strong>: Bump the minimum Metro version to 0.87.1, so upgrading projects resolve the same Metro as freshly created ones (<a href="https://github.com/react/react-native/commit/f2439a83cffc8f2bf8355a984a055ae7174bb4d9">f2439a83cf</a> by <a href="https://github.com/robhogan">@robhogan</a>)

Fixed

* <strong>TurboModules</strong>: Revert the <code>RCTArrayBuffer</code> codegen change, restoring <code>NSMutableData *</code> for ObjC TurboModule methods that take or return an <code>ArrayBuffer</code>. 0.88 is a non-breaking release, and the change stopped modules that adopted ObjC <code>ArrayBuffer</code> support in 0.87 from compiling (<a href="https://github.com/react/react-native/commit/639cdedb506d6441e27eeb579225aa6a7def3ff9">639cdedb50</a>, <a href="https://github.com/react/react-native/commit/19a31849817b8cf0eaef56305330c4b39d826fe8">19a3184981</a> by <a href="https://github.com/fabriziocucci">@fabriziocucci</a>)
* <strong>TurboModules</strong>: Revert the rejection of <code>ArrayBuffer</code> as a TurboModule <code>EventEmitter</code> payload. C++ TurboModules could declare <code>EventEmitter&lt;ArrayBuffer&gt;</code> in 0.87 and it generated working code, so rejecting it at codegen time broke those builds (<a href="https://github.com/react/react-native/commit/070af03ab3b9584473b0ffb1a837ac252d127ec9">070af03ab3</a> by <a href="https://github.com/fabriziocucci">@fabriziocucci</a>)
* <strong>TypeScript</strong>: Restore the <code>.js</code> fallback for legacy deep imports of untyped modules, so <code>react-native/Libraries/*</code> specifiers resolve again under the <code>react-native-legacy-deep-imports</code> condition (<a href="https://github.com/react/react-native/commit/579212e15c9197d6c614cfeb4561e4a85956ee3b">579212e15c</a> by <a href="https://github.com/fabriziocucci">@fabriziocucci</a>)
