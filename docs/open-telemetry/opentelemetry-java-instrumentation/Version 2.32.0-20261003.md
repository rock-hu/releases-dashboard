# Version 2.32.0

## release on 20261003
## description
## changes
This release targets the OpenTelemetry SDK 1.66.0.

Note that many artifacts have the <code>-alpha</code> suffix attached to their version number, reflecting that they will continue to have breaking changes. Please see <a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/blob/main/VERSIONING.md#opentelemetry-java-instrumentation-versioning">VERSIONING.md</a> for more details.

:warning: Breaking changes to non-stable APIs

* Remove the deprecated <code>HostIdResource.REGISTRY_QUERY</code> constant. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19778" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19778/hovercard">#19778</a>)
* The <code>ExperimentalJmxMetricHandler</code> SPI now requires implementations to provide <code>getMetricNames()</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19781" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19781/hovercard">#19781</a>)
* Add the required <code>isRequestStreaming(REQUEST)</code> method to <code>GenAiAttributesGetter</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19879" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19879/hovercard">#19879</a>)
* The experimental <code>java.common.messaging.headers/development</code> YAML selector no longer configures header capture. Use <code>java.common.messaging.headers</code> instead. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20260" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20260/hovercard">#20260</a>)

🚫 Deprecations

* Deprecate <code>otel.jmx.target.system</code> in favor of <code>otel.jmx.metrics.experimental.included</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19783" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19783/hovercard">#19783</a>)
* Deprecate <code>otel.instrumentation.elasticsearch.capture-search-query</code>. It will be removed in 3.0, when search query bodies are always captured. There is no replacement. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19675" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19675/hovercard">#19675</a>)
* Deprecate <code>otel.instrumentation.opensearch.capture-search-query</code>. It will be removed in 3.0, when search query bodies are always captured. There is no replacement. Sanitization remains enabled by default and configurable with <code>otel.instrumentation.opensearch.query-sanitization.enabled</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19837" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19837/hovercard">#19837</a>)
* Deprecate <code>otel.jmx.enabled</code> in favor of <code>otel.instrumentation.jmx.enabled</code> to align with other instrumentation enablement properties. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19945" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19945/hovercard">#19945</a>)
* Deprecate automatic rewriting of <code>VirtualField.find(Class, Class)</code> calls in inlined javaagent advice. Instead, look up the <code>VirtualField</code> once and store it in a helper class's <code>static final</code> field. The <code>find</code> method itself remains supported. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19980" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19980/hovercard">#19980</a>)
* Deprecate the Elasticsearch REST library instrumentation. Use the Elasticsearch Java API Client's native OpenTelemetry support, or the Java agent for direct <code>RestClient</code> usage. Java agent instrumentation is unaffected. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/19995" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/19995/hovercard">#19995</a>)
* Deprecate <code>otel.instrumentation.messaging.experimental.receive-telemetry.enabled</code> in favor of <code>otel.instrumentation.common.messaging.experimental.receive-telemetry.enabled</code>. For headers, replace <code>otel.instrumentation.messaging.experimental.headers.included</code> and <code>.excluded</code> with <code>otel.instrumentation.common.messaging.headers.included</code> and <code>.excluded</code>. Also deprecate <code>otel.instrumentation.messaging.experimental.capture-headers</code> in favor of <code>otel.instrumentation.common.messaging.headers.included</code>. Stable selectors take precedence per leaf. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20060" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20060/hovercard">#20060</a>, <a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20260" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20260/hovercard">#20260</a>)
* Deprecate the <code>.included</code> / <code>.excluded</code> properties under <code>otel.instrumentation.log4j-appender.experimental.map-message-attributes</code>, <code>otel.instrumentation.logback-appender.experimental.key-value-pair-attributes</code>, <code>otel.instrumentation.logback-appender.experimental.logstash-marker-attributes</code>, and <code>otel.instrumentation.logback-appender.experimental.logstash-structured-argument-attributes</code> in favor of the stable and unified <code>otel.instrumentation.common.logging.structured-attributes.included</code> / <code>.excluded</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20066" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20066/hovercard">#20066</a>)
* Deprecate <code>otel.instrumentation.couchbase.experimental-span-attributes</code> in favor of <code>otel.instrumentation.couchbase.emit-experimental-telemetry</code>, a broader name for experimental attributes and internal spans from the underlying Couchbase client. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20117" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20117/hovercard">#20117</a>)
* Deprecate <code>otel.traces.sampler=linksbased_parentbased_always_on</code> with no replacement and declarative <code>rule_based_routing</code> in favor of the SDK incubator composite/development <code>rule_based</code> sampler, whose configuration and matching behavior differ. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20249" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20249/hovercard">#20249</a>)
* Promote controller and view telemetry configuration to the stable properties <code>otel.instrumentation.common.controller-telemetry.enabled</code> and <code>otel.instrumentation.common.view-telemetry.enabled</code>, deprecating <code>otel.instrumentation.common.experimental.controller-telemetry.enabled</code> and <code>otel.instrumentation.common.experimental.view-telemetry.enabled</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20258" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20258/hovercard">#20258</a>)
* Promote Java agent span suppression configuration to the stable property <code>otel.instrumentation.common.span-suppression-strategy</code>, deprecating <code>otel.instrumentation.experimental.span-suppression-strategy</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20259" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20259/hovercard">#20259</a>)
* Deprecate <code>otel.instrumentation.oshi.experimental-metrics.enabled</code>, <code>ProcessMetrics</code>, and its <code>registerObservers(...)</code> methods in favor of <code>jvm.memory.used</code> and <code>jvm.cpu.time</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20323" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20323/hovercard">#20323</a>)
* Deprecate <code>SystemMetrics.registerObservers(Meter)</code> in the OSHI library instrumentation in favor of <code>SystemMetrics.registerObservers(OpenTelemetry)</code>. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20263" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20263/hovercard">#20263</a>)
* In declarative configuration YAML, deprecate dotted selectors in the <code>distribution.javaagent.instrumentation.enabled</code> and <code>.disabled</code> lists. Use <code>reactor_3_1</code> instead of <code>reactor_3.1</code>. Flat-property names such as <code>otel.instrumentation.reactor-3.1.enabled</code> are unchanged. (<a href="https://github.com/open-telemetry/opentelemetry-java-instrumentation/pull/20326" data-hovercard-type="pull_request" data-hovercard-url="/open-telemetry/opentelemetry-java-instrumentation/pull/20326/hovercard">#20326</a>)
