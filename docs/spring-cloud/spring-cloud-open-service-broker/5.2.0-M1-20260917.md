Spring Cloud Open Service Broker 5.2.0-M1

Spring Cloud Open Service Broker 5.2.0-M1 is the first milestone release in the 5.2.x line. Version 5.2.0-M1 is built against Spring Boot 4.1 and requires Java 17+. It adds support for OSB API v2.17, introducing Service Binding rotation and additional service instance metadata. The OSB API v2.17 upgrade is purely additive and does not introduce any breaking changes from OSB API v2.16.

Highlights

* <strong>OSB API v2.17 support</strong>, including Service Binding rotation
* Added <code>maintenance_info</code> and <code>metadata</code> to the fetch service instance response
* Added <code>attributes</code> to Service Instance Metadata, alongside the existing <code>labels</code>
* Fixed several optional fields that always serialized as an empty object/array instead of being omitted when unset
* Fully backwards compatible with OSB API v2.16 — no breaking changes

OSB API v2.17 Support

Service Binding Rotation

* Added <code>binding_rotatable</code> to the Service Plan object, indicating whether bindings created against a plan support rotation.
* Added <code>predecessor_binding_id</code> to the create service instance binding request, used to rotate a Service Binding by referencing a non-expired binding of the same service instance.
* Added <code>renew_before</code> to the Binding Metadata object, alongside the existing <code>expires_at</code>.

Fetch Service Instance

* Added <code>maintenance_info</code> and <code>metadata</code> to the fetch service instance response, matching fields already supported on the create and update service instance responses.

Service Instance Metadata

* Added <code>attributes</code> to Service Instance Metadata, alongside the existing <code>labels</code>.

Citation Corrections

* Corrected several <code>Since OSB API</code> javadoc citations: <code>GetServiceInstanceRequest</code>/<code>GetServiceInstanceBindingRequest</code>'s <code>service_id</code>/<code>plan_id</code> query-string parameters were tagged 2.14 but were actually added in 2.16, and <code>BindingMetadata.expires_at</code>, <code>CreateServiceInstanceBindingResponse.metadata</code>, and <code>GetServiceInstanceBindingResponse.metadata</code> were untagged despite being introduced in 2.16.

Bug Fixes

* Fixed <code>ServiceInstanceMetadata.labels</code>/<code>.attributes</code>, <code>GetServiceInstanceResponse.parameters</code>, and <code>MethodSchema.parameters</code> always serializing as an empty <code>{}</code> instead of being omitted when unset.
* Fixed <code>SharedVolumeDevice</code>, which had no JSON inclusion configuration at all, so <code>volume_id</code> serialized as <code>null</code> and <code>mount_config</code> as an empty <code>{}</code> even when unset.
* Fixed the <code>ServiceDefinition</code> and <code>Plan</code> no-arg constructors, which passed non-null empty collections for optional fields (<code>tags</code>, <code>metadata</code>, <code>requires</code>) instead of <code>null</code>, unlike their respective builders.

Documentation

* Documented the new Service Binding rotation fields in the reference documentation.
* Fixed a stale ISO 8601 pattern typo in <code>BindingMetadata</code>'s <code>expires_at</code> documentation.
* Updated stale <code>v2.13</code> spec references in the API version verification docs.
* Updated the README version compatibility matrix.

Upgrade Notes

OSB API v2.17 is a minor, additive-only revision of the spec: every change in this release is a new optional field (<code>binding_rotatable</code>, <code>predecessor_binding_id</code>, <code>renew_before</code>, <code>maintenance_info</code>/<code>metadata</code> on fetch, <code>attributes</code>). Nothing existing was renamed, removed, or had its type or semantics changed. Service brokers built against prior versions of this library, and platforms built against OSB API v2.16, are unaffected by this upgrade and require no changes to keep working.
