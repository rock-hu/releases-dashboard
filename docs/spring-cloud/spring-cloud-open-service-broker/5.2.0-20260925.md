## release on 20260925

## changes
Spring Cloud Open Service Broker 5.2.0

Spring Cloud Open Service Broker 5.2.0 is now GA. Version 5.2.0 is built against Spring Boot 4.1 and requires Java 17+. It adds support for OSB API v2.17 — an additive-only upgrade from v2.16, so nothing existing was renamed, removed, or changed; brokers built against 5.1.x are unaffected unless they opt into the new fields.

Versions

| Component | Version |
|------------------|---------|
| Spring Boot | 4.1.1 |

Highlights

* <strong>OSB API v2.17 support</strong>: binding rotation (<code>binding_rotatable</code>, <code>predecessor_binding_id</code>, <code>renew_before</code>), <code>maintenance_info</code>/<code>metadata</code> on the fetch-instance response, and <code>attributes</code> on service instance metadata
* <strong><code>Retry-After</code> header support</strong> for last-operation polling (OSB API v2.15), on both service instance and service binding last-operation responses

OSB API Compliance

* Added <code>binding_rotatable</code> to the Service Plan object, indicating whether a plan supports binding rotation.
* Added <code>predecessor_binding_id</code> to the create-binding request, letting a platform request rotation of an existing binding.
* Added <code>renew_before</code> to the binding response, alongside <code>expires_at</code>.
* Added <code>maintenance_info</code> and <code>metadata</code> to the fetch-service-instance response, matching the fields already available on create/update instance responses.
* Added <code>attributes</code> to <code>ServiceInstanceMetadata</code>, alongside the existing <code>labels</code>.
* Added <code>Retry-After</code> header support: <code>GetLastServiceOperationResponse</code> and <code>GetLastServiceBindingOperationResponse</code> gained an optional <code>retryAfter</code> (seconds) field, applied to the outgoing HTTP response only on the two last-operation polling endpoints. New constructor overloads were added rather than changing existing ones — the prior constructors are now deprecated but still work, so no existing caller's source or binary compatibility is affected.
* Bumped <code>BrokerApiVersion.API_VERSION_CURRENT</code> to <code>2.17</code>.

Documentation

* Documented service binding rotation.
* Fixed stale v2.13 references in the API version verification docs.
* Added 5.2.x to the README version compatibility matrix.

Dependency Upgrades

* Bumped <code>nl.jqno.equalsverifier:equalsverifier</code> from 4.5.1 to 4.5.2.

Upgrade Notes

The OSB API v2.17 upgrade is additive-only: every new field above is optional, and nothing in the v2.16 wire format or this library's public Java API was renamed, removed, or had its behavior changed. Existing brokers built against 5.1.x can upgrade without any code changes, and only need to touch the new fields if they want to advertise binding rotation or the new instance-metadata/fetch fields. The deprecated <code>GetLastServiceOperationResponse</code>/<code>GetLastServiceBindingOperationResponse</code> constructors predating <code>retryAfter</code> still work as before.
