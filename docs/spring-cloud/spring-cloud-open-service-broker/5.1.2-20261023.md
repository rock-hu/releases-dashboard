Spring Cloud Open Service Broker 5.1.2

Spring Cloud Open Service Broker 5.1.2 is now GA. Version 5.1.2 is built against Spring Boot 4.1 and requires Java 17+. It is a maintenance release in the 5.1.x line that fixes a duplicated <code>X-Broker-API-Request-Identity</code> response header on Spring MVC brokers and picks up Spring Boot 4.1.2. The OSB API version is unchanged at v2.16.

Highlights

* <strong>Fixed a duplicated <code>X-Broker-API-Request-Identity</code> response header</strong> on Spring MVC brokers (introduced when the header echo was enabled in 5.1.1)
* <strong>Spring Boot 4.1.2</strong> (Spring Framework 7.0.10)
* Gradle 9.8.2 build infrastructure

Bug Fixes

* Fixed the <code>X-Broker-API-Request-Identity</code> response header being sent twice (for example <code>request-id, request-id</code>) on Spring MVC brokers. Broker controllers return reactive types, so Spring MVC handles each request asynchronously and dispatches it a second time through the same interceptors, and <code>RequestIdentityInterceptor</code> added the header on both dispatches. It now sets the header, so the request identity is echoed exactly once, as the spec's <a href="https://github.com/openservicebrokerapi/servicebroker/blob/v2.16/spec.md#request-identity">Request Identity</a> section describes. WebFlux brokers were not affected.

Build Improvements

* Upgraded Gradle from 9.7.1 to 9.8.2.

Dependency Upgrades

* Bumped Spring Boot from 4.1.1 to 4.1.2.
* Bumped <code>io.rest-assured:rest-assured</code> from 6.0.1 to 6.2.0.
* Bumped <code>nl.jqno.equalsverifier:equalsverifier</code> from 4.5.1 to 4.5.2.

Upgrade Notes

This is a drop-in upgrade from 5.1.1: the public API of this library and the OSB API version (v2.16) are unchanged. The one observable behavior change is on the Spring MVC stack: the <code>X-Broker-API-Request-Identity</code> response header now appears once instead of twice. This only matters to clients that read every value of the header, since a client that reads the first value is unaffected. Brokers on 5.1.1 that use Spring MVC saw the duplicate and will see it disappear.
