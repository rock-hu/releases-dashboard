# v4.0.1 Update 1

## release on 20260918
## description
## changes
v4.0.1 Swagger Update 1 - 2026-09-18

This update covers Swagger/OpenAPI refinements for the Confirmation of Funds (CBPII) API in v4.0.1 and addresses v401_KI_2 in Account Information (AIS)

Added

* Added CBPII OpenAPI tags for <code>Funds Confirmation Consents</code> and <code>Funds Confirmations</code> to improve Swagger UI grouping and navigation.
* Added optional <code>x-jws-signature</code> request header support across all CBPII operations to align with the Open Banking spec pages/standard.
* Added optional <code>x-jws-signature</code> response header support across CBPII success and error responses to align with the Open Banking spec pages/standard.
* Added CBPII OpenAPI examples for key parameters, headers, error payloads and schema fields.

Changed

* Updated CBPII endpoint descriptions for consent creation, consent retrieval, consent deletion and funds confirmation creation to provide clearer behaviour and outcome detail for Swagger UI and AI agent consumers.
* Updated the duplicate CBPII OpenAPI JSON output generated from the YAML source so the YAML and JSON Swagger artefacts stay aligned.
* Standardised CBPII OpenAPI description formatting for consistency (single-line where suitable, <code>&gt;-</code>/<code>|-</code> block scalar usage where appropriate, paragraph spacing, inline code formatting, and emphasised notes).
* Updated CBPII security scheme, error model and account proxy descriptions to align with Open Banking/FAPI context and improve clarity.
* Updated <code>x-jws-signature</code> to be optional in CBPII request/response modelling to align with the Open Banking spec pages/standard. Additionally a fully formed example value has been provided in the OpenAPI specification.
* Updated CBPII enum descriptions to link directly to the relevant codeset CSV files.
* Refactored CBPII <code>OBInternalAccountIdentification4Code</code> into a reusable schema reference.
* Refactored CBPII Confirmation of Funds OpenAPI data dictionary schemas to use reusable component references aligned to the spec pages:
  * <code>OBFundsConfirmationConsent1/Data</code> now references <code>OBFundsConfirmationConsentData1</code>
  * <code>OBFundsConfirmationConsentResponse1/Data</code> now references <code>OBFundsConfirmationConsentDataResponse1</code>
  * <code>OBFundsConfirmation1/Data</code> now references <code>OBFundsConfirmationData1</code>
  * <code>OBFundsConfirmationResponse1/Data</code> now references <code>OBFundsConfirmationDataResponse1</code>
  * <code>OBFundsConfirmationConsent1/Data/DebtorAccount</code> and <code>OBFundsConfirmationConsentResponse1/Data/DebtorAccount</code> now reference <code>OBCashAccountDebtorWithName</code>
  * <code>OBFundsConfirmation1/Data/InstructedAmount</code> and <code>OBFundsConfirmationResponse1/Data/InstructedAmount</code> now reference <code>OBActiveOrHistoricCurrencyAndAmount</code>
  * <code>OBFundsConfirmation1/Data/InstructedAmount/Amount</code> and <code>OBFundsConfirmationResponse1/Data/InstructedAmount/Amount</code> now reference <code>OBActiveCurrencyAndAmount_SimpleType</code>
  * <code>OBFundsConfirmation1/Data/InstructedAmount/Currency</code> and <code>OBFundsConfirmationResponse1/Data/InstructedAmount/Currency</code> now reference <code>ActiveOrHistoricCurrencyCode</code>
  * Updated link to RFC 6750 in the <code>Authorization</code> header description.

Removed

* Removed <strong>unused</strong> CBPII response/schema components <code>404Error</code> and <code>Identification_0</code>.
* Removed <strong>unused</strong> CBPII header parameter <code>x-idempotency-key</code> (CBPII has no idempotent endpoints).

Fixed

* [v401_KI_2] Corrected AIS <code>OBCashAccount6_1</code> in Update 1 by making <code>SchemeName</code> and <code>Identification</code> required for <code>OBReadTransaction6/Data/Transaction/DebtorAccount</code>; this completes the <code>OBCashAccountDebtorWithName</code> alignment that was intended for the v4.0.1 baseline.
