# SRU2026-10.4.4

## release on 20260820
## description
## changes
10.4.4 - August 2026

* (PW-3433) Fix: <code>OptionJPartyField.getValueByCodeword</code> no longer shifts the codeword/value pairs that follow a codeword with a blank value (for example "/CITY/" followed by "/CTRY/US" returned "CTRY" for CITY and null for CTRY); a codeword present with a blank value now returns an empty string
* (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5159913728" data-permission-text="Title is private" data-url="https://github.com/prowide/prowide-core/issues/341" data-hovercard-type="issue" data-hovercard-url="/prowide/prowide-core/issues/341/hovercard" href="https://github.com/prowide/prowide-core/issues/341">GH-341</a>) Feat: <code>SwiftMessageUtils.money</code> revised for category 7: amount added for MT744, MT760, MT765 and MT786; changed to field 32B for MT750 and MT752, and to 34B for MT769; removed for MT707
* (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5093638824" data-permission-text="Title is private" data-url="https://github.com/prowide/prowide-core/issues/338" data-hovercard-type="issue" data-hovercard-url="/prowide/prowide-core/issues/338/hovercard" href="https://github.com/prowide/prowide-core/issues/338">GH-338</a>) Fix: no-arg getters of subsequences with delimiters shared by another sequence in the same message are now resolved within their parent sequence, not the whole block 4; fixes <code>MT360</code>/<code>MT361</code> <code>getSequenceE1()</code>, <code>getSequenceF1()</code> and <code>getSequenceF2()</code> returning sequence B/C content. Affected subsequences are flagged with <code>@NonUniqueSeparator</code>
* (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="4770188488" data-permission-text="Title is private" data-url="https://github.com/prowide/prowide-core/issues/327" data-hovercard-type="issue" data-hovercard-url="/prowide/prowide-core/issues/327/hovercard" href="https://github.com/prowide/prowide-core/issues/327">GH-327</a>) Fix: Field 44J serialization now adds the mandatory starting slash in the narrative line when the narrative component is set without it
* Fix: large XML documents with many escaped characters (e.g. camt/pacs statements) no longer fail to parse on Java 24 and newer JVMs
* Chore: no-arg getters of sequences with a non-unique 16R/S delimiter are now generated with the same parent sequence scoping, replacing the hand-written resolvers in <code>SequenceUtils</code>, which are now deprecated
