# SRU2026-9.7.1

## release on 20261007
## description
## changes
9.7.1 - October 2026

* (PW-3433) Fix: <code>OptionJPartyField.getValueByCodeword</code> no longer shifts the codeword/value pairs that follow a codeword with a blank value (for example "/CITY/" followed by "/CTRY/US" returned "CTRY" for CITY and null for CTRY); a codeword present with a blank value now returns an empty string
* (PW-3251) Feat: Added <code>FileFormat.MX_UNWRAPPED</code> to identify MX payloads where the Header and Document arrive as sibling root elements with no enclosing envelope
* (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5159913728" data-permission-text="Title is private" data-url="https://github.com/prowide/prowide-core/issues/341" data-hovercard-type="issue" data-hovercard-url="/prowide/prowide-core/issues/341/hovercard" href="https://github.com/prowide/prowide-core/issues/341">GH-341</a>) Feat: <code>SwiftMessageUtils.money</code> revised for category 7: amount added for MT744, MT760, MT765 and MT786; changed to field 32B for MT750 and MT752, and to 34B for MT769; removed for MT707
* (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5093638824" data-permission-text="Title is private" data-url="https://github.com/prowide/prowide-core/issues/338" data-hovercard-type="issue" data-hovercard-url="/prowide/prowide-core/issues/338/hovercard" href="https://github.com/prowide/prowide-core/issues/338">GH-338</a>) Fix: no-arg getters of subsequences with delimiters shared by another sequence in the same message are now resolved within their parent sequence, not the whole block 4; fixes <code>MT360</code>/<code>MT361</code> <code>getSequenceE1()</code>, <code>getSequenceF1()</code> and <code>getSequenceF2()</code> returning sequence B/C content. Affected subsequences are flagged with <code>@NonUniqueSeparator</code>
* (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="4770188488" data-permission-text="Title is private" data-url="https://github.com/prowide/prowide-core/issues/327" data-hovercard-type="issue" data-hovercard-url="/prowide/prowide-core/issues/327/hovercard" href="https://github.com/prowide/prowide-core/issues/327">GH-327</a>) Fix: Field 44J serialization now adds the mandatory starting slash in the narrative line when the narrative component is set without it
* Fix: the message nested in the block 4 of the system messages MT021, MT056 and MT096 is no longer truncated at the first closing brace, so these messages are parsed and written back intact; the tag value is read balancing the curly braces for the tag names where SWIFT defines nested blocks (the block identifiers 1 to 5 and the field 270), while any other tag keeps the historical reading, ending at the first closing brace
* Fix: MT300 subsequence D1, field 57a is mandatory and the subsequence itself is mandatory within sequence D. <code>MT300.SequenceD1</code> is now delimited by 17A..57a with 58a as the only optional tail, where it previously ended at 32B and took 53a, 56a, 57a and 58a as tail
* Fix: MT306 subsequence L1 and MT320 subsequence I1 are mandatory within their parent sequence, and the 20C/20U Transaction Reference fieldset item of MT548 is not repetitive; the three corrections are reflected in the message javadoc, the generated accessors are unchanged
* Fix: MT420 sequence <code>Loop1</code> renamed to <code>A</code>, as named in the format specification. <code>MT420.Loop1</code> is now <code>MT420.SequenceA</code> and <code>getLoop1List()</code> is now <code>getSequenceAList()</code>; <code>MtSequenceEnum.MT420</code> reports <code>A</code> and <code>B</code> instead of <code>B</code> alone
* Fix: <code>FieldEnum</code> includes <code>F29Z</code>, for field 29Z Bank/Customer Contact, added to the standard in SRU2026
* Fix: large XML documents with many escaped characters (e.g. camt/pacs statements) no longer fail to parse on Java 24 and newer JVMs
* Feat: <code>SwiftParser.parseBlock3</code> and <code>SwiftParser.parseBlock5</code> also accept the block content without the block identifier, as it is found in the nested blocks of an MT021 or MT096, and return an empty block for a null content
* Feat: new <code>IsoUtils#getCountryName(code)</code> with the ISO 3166-1 English short name of a country, looked up by its alpha-2, alpha-3 or numeric code
* Feat: <code>IsoUtils#isUserAssignedCountryCode(code)</code> is now public, for the ISO 3166-1 user assigned range XA to XZ; it no longer accepts an upper case letter of another alphabet after the X, so <code>isValidISOCountry</code> rejects codes such as "XЖ"
* Chore: no-arg getters of sequences with a non-unique 16R/S delimiter are now generated with the same parent sequence scoping, replacing the hand-written resolvers in <code>SequenceUtils</code>, which are now deprecated
* Chore: scheme constants regenerated. Adds <code>QAIS</code>, <code>QFOR</code> and <code>QRET</code>, from the qualifier list of field 36B/36D in MT567, which previously had none declared. Removes <code>AMAM</code>, <code>AMTL</code>, <code>FRWD</code>, <code>INCH</code>, <code>INSF</code>, <code>INSI</code>, <code>NELI</code> and <code>STLD</code>: their only source was field 23E in sequence B of MT416, which listed the full generic instruction codes instead of the NACC, NPAY and OTHR the specification allows there
* Chore: the <code>creationUser</code> mapping in <code>SwiftMessageStatusInfo</code>, <code>SwiftMessageNote</code> and <code>SwiftMessageRevision</code> declares length 100 instead of 40, to fit usernames such as e-mail addresses
