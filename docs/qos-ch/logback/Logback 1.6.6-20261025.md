# Logback 1.6.6

## release on 20261025
## description
## changes
2026-10-25 Release of logback version 1.6.6

• <code>LoggingEventVO</code> now rejects, during deserialization, throwable proxies whose cause or suppressed entries point back into the graph of proxies, for example to their own parent. Such graphs cannot be produced by logback itself. However, a crafted stream sent to a socket receiver could use serialization back-references to build them, after which <code>DefaultThrowableRenderer</code> and <code>SyslogAppender</code> would loop forever and the recursive converters would overflow the stack. These streams are now rejected with an <code>InvalidObjectException</code>. Circular exceptions logged by the application are still transmitted correctly. This issue was reported and fixed in <a href="https://github.com/qos-ch/logback/pull/1079" data-hovercard-type="pull_request" data-hovercard-url="/qos-ch/logback/pull/1079/hovercard">PR #1079</a> by <a href="https://github.com/arfa-21">arfa-21</a>.

• <code>FileNamePattern</code> now escapes characters with a special meaning in regular expressions, such as <code>(</code>, <code>[</code> or <code>+</code>, when converting the literal parts of a file name pattern into a regex. Previously, <code>RollingFileAppender</code> failed to start when the path contained an unbalanced parenthesis, as in <code>C:/Users/Michael(Financ</code>. This issue was reported in <a href="https://github.com/qos-ch/logback/issues/914" data-hovercard-type="issue" data-hovercard-url="/qos-ch/logback/issues/914/hovercard">issues/914</a> by <a href="https://github.com/danamlund">danamlund</a>. Moreover, with <code>SizeAndTimeBasedRollingPolicy</code> and a pattern such as <code>app.%d.(%i).log</code>, existing archives were not recognized. After a restart within the same period, the next rollover could overwrite an existing archive, and <em>maxHistory</em> and <em>totalSizeCap</em> never removed such archives. This issue was reported in <a href="https://github.com/qos-ch/logback/issues/933" data-hovercard-type="issue" data-hovercard-url="/qos-ch/logback/issues/933/hovercard">issues/933</a> by <a href="https://github.com/GeoffreyBoulay">GeoffreyBoulay</a>. The fix was contributed in <a href="https://github.com/qos-ch/logback/pull/1077" data-hovercard-type="pull_request" data-hovercard-url="/qos-ch/logback/pull/1077/hovercard">PR #1077</a> by <a href="https://github.com/CCCLL">Jialin Chen</a>. Regex metacharacters in <code>%d{...}</code> date patterns are now escaped as well.

• The conversion of date patterns into regular expressions now follows the rules of <code>DateTimeFormatter</code>, which logback uses to format dates, instead of those of <code>SimpleDateFormat</code>. In particular, the <code>L</code> (stand-alone month) pattern letter is now supported.

• <code>SyslogOutputStream</code> now connects its <code>DatagramSocket</code> to the syslog host. Previously, the socket was bound to the wildcard address, so that hardened environments saw an unconnected UDP listener on all interfaces for as long as the application ran. This issue was reported in <a href="https://github.com/qos-ch/logback/issues/939" data-hovercard-type="issue" data-hovercard-url="/qos-ch/logback/issues/939/hovercard">issues/939</a> by <a href="https://github.com/joao-rebelo">joao-rebelo</a>. The fix was contributed in <a href="https://github.com/qos-ch/logback/pull/1076" data-hovercard-type="pull_request" data-hovercard-url="/qos-ch/logback/pull/1076/hovercard">PR #1076</a> by <a href="https://github.com/Lyin-OTTF">Lyin-OTTF</a>.

If the socket cannot be connected, for example because the network is not yet available, <code>SyslogOutputStream</code> falls back to an unconnected socket and <code>SyslogAppenderBase</code> emits a warning. When a datagram sent on a connected socket fails due to an ICMP "port unreachable" message caused by an earlier datagram, the datagram is sent once more so that no message is lost. If the retry also fails, a single warning is emitted instead of one error per event.

• <code>OutputStreamAppender</code> now stops its encoder when the appender is stopped. Previously, encoders holding resources until they were stopped, such as those of logstash-logback-encoder, were never released, causing heap growth at each reconfiguration. This issue was fixed in <a href="https://github.com/qos-ch/logback/pull/1072" data-hovercard-type="pull_request" data-hovercard-url="/qos-ch/logback/pull/1072/hovercard">PR #1072</a> by <a href="https://github.com/samyuh">Samuel Fernandes</a>.

• During variable substitution, an unmatched right curly brace now causes an error to be reported, with the original value left unchanged. Previously, the brace and all subsequent characters were silently dropped, so that <code>%m}some text</code> became <code>%m</code>. This issue was reported in <a href="https://github.com/qos-ch/logback/issues/836" data-hovercard-type="issue" data-hovercard-url="/qos-ch/logback/issues/836/hovercard">issues/836</a> by <a href="https://github.com/philsttr">philsttr</a>.

• <code>LogbackMDCAdapter</code> now stores MDC entries in a <code>LinkedHashMap</code>, so that the <code>%X</code> converter outputs them in insertion order. This issue was reported in <a href="https://jira.qos.ch/browse/LOGBACK-1337" rel="nofollow">LOGBACK-1337</a> and fixed by <a href="https://github.com/motlin">Craig P. Motlin</a>.
