Upgrade notes

Spring Integration 7.0.6+ introduced a security fix that restricts <code>DefaultJmsHeaderMapper</code>'s inbound property mapping to an explicit allowlist, which defaults to only the <code>content_type</code> property. Remote chunking and remote partitioning over JMS rely on Spring Integration's <code>correlationId</code>, <code>sequenceNumber</code> and <code>sequenceSize</code> message headers to match replies from workers back to the manager's reply aggregator. As user-defined JMS properties, these headers were no longer mapped back into message headers by default, causing jobs to hang or fail with <code>IllegalStateException: Null correlation not allowed</code>.

If you use remote chunking or remote partitioning over JMS, configure your <code>Jms.messageDrivenChannelAdapter</code> beans with a header mapper that maps these headers:

    Jms.messageDrivenChannelAdapter(connectionFactory)
         .headerMapper(new DefaultJmsHeaderMapper("*"))
         .destination("replies")

If mapping all headers is too permissive for your security requirements, restrict the allowlist to just what Spring Batch needs:  

<code>new DefaultJmsHeaderMapper("correlationId", "sequenceNumber", "sequenceSize")</code>.
