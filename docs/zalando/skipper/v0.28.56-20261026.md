perf(routesrv): only recompress zones whose routes actually changed (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="6027436768" data-permission-text="Title is private" data-url="https://github.com/zalando/skipper/issues/4378" data-hovercard-type="pull_request" data-hovercard-url="/zalando/skipper/pull/4378/hovercard" href="https://github.com/zalando/skipper/pull/4378">#4378</a>)

formatAndSet rebuilt every zone's compressed routing table whenever the  

global table changed, even if most zones' content was identical to what  

was already stored. In the common steady-state case - one availability  

zone's endpoints change while others don't - this wasted a full  

eskip.Fprint + gzip pass per untouched zone, and needlessly advanced  

their Last-Modified, defeating If-Modified-Since caching for those  

zones.

formatAndSet now hashes each zone once and only recompresses, re-counts,  

and re-timestamps a zone whose hash differs from what is already stored.  

Zones no longer present in zoneAwareRoutes are deleted from all internal  

maps so requests for them fall back to the global routing table instead  

of serving stale data.
