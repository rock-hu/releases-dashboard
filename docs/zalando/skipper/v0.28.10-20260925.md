Symptom

A request body larger than <code>-max-matcher-buffer-size</code> (2MiB by default)  

does not reach the backend of a <code>blockContent</code> route. Route:

    r: * -> blockContent("Malicious Content") -> "http://backend"

The backend prints how many bytes it reads from the body. Through a  

skipper built from master with the default buffer size:

    POST 1048576 bytes: backend received 1048576 bytes
    POST 2097152 bytes: backend received 2097152 bytes
    POST 3145728 bytes: backend received 0 bytes

The client gets the backend's response as if the upload had been  

forwarded. Depending on how the reads line up, the backend gets nothing  

or only the tail of the body: with a 1024 byte buffer a 12000 byte body  

arrives as 856 bytes.

This is the silent form of <a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="1929752244" data-permission-text="Title is private" data-url="https://github.com/zalando/skipper/issues/2655" data-hovercard-type="issue" data-hovercard-url="/zalando/skipper/issues/2655/hovercard" href="https://github.com/zalando/skipper/issues/2655">#2655</a>. The <code>ContentLength=100003 with Body length 0</code> error reported there went away when <a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="2067353903" data-permission-text="Title is private" data-url="https://github.com/zalando/skipper/issues/2828" data-hovercard-type="pull_request" data-hovercard-url="/zalando/skipper/pull/2828/hovercard" href="https://github.com/zalando/skipper/pull/2828">#2828</a> started to remove  

the <code>Content-Length</code> header, but the body is still dropped.

Cause

<code>io/read_stream.go</code>, <code>matcher.fill</code>. In best effort mode, when <code>pending</code>  

grows beyond the max buffer size, the matcher inspects it and then  

resets it:

    _, err := m.f(m.pending.Bytes())
    if err != nil {
    	return err
    }
    m.pending.Reset()

<code>ready</code>, the buffer that <code>Read</code> serves from, is only filled from  

<code>pending</code> once the input is exhausted, so everything inspected before  

that point is discarded. Only what was read after the last reset is  

delivered.

Fix

Hand the inspected data to <code>ready</code> instead of discarding it, the same  

way the end of input path does.

The existing <code>maxBuffer</code> case in <code>TestMatcherErrorCases</code> expected a nil  

error from reading a 17 byte body that contains the blocked string  

through a 5 byte buffer. It passed because only the last two bytes,  

<code>ss</code>, were delivered. With the body delivered the blocked string is  

found, so the case now expects <code>ErrBlocked</code>, like its <code>maxBufferAbort</code>  

twin expects <code>ErrMatcherBufferFull</code>.
