Description

This PR documents the data client runtime timing metrics introduced in  

<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="4758891775" data-permission-text="Title is private" data-url="https://github.com/zalando/skipper/issues/4087" data-hovercard-type="pull_request" data-hovercard-url="/zalando/skipper/pull/4087/hovercard" href="https://github.com/zalando/skipper/pull/4087">#4087</a> in the operations guide (<code>docs/operation/operation.md</code>). These  

metrics measure execution time for loading initial routes and applying  

incremental route updates across data clients, providing better  

observability into route sync latency.

cc <a class="user-mention notranslate" data-hovercard-type="user" data-hovercard-url="/users/MustafaSaber/hovercard" data-octo-click="hovercard-link-click" data-octo-dimensions="link_type:self" href="https://github.com/MustafaSaber">@MustafaSaber</a>, please take a look when you get a chance!

Changes

Added documentation under <code>## Monitoring</code> -> <code>### Data client metrics</code>  

for:

* <code>routes.load_all.&lt;client&gt;</code>: Timer measuring execution time for loading  
  all routes from the data client.
* <code>routes.load_update.&lt;client&gt;</code>: Timer measuring execution time for  
  loading incremental route updates from the data client.

Included details clarifying that <code>&lt;client&gt;</code> is resolved via  

<code>NamedDataClient.Name()</code> (e.g., <code>kubernetes</code> or <code>inline</code>), and that data  

clients not implementing the <code>NamedDataClient</code> interface report as  

<code>unknown</code> (e.g., <code>routes.load_all.unknown</code>).
