<strong>Problem.</strong> <code>TestServerResponseFilter</code> is flaky: occasionally the  

<code>opaServeResponse</code> filter returns <code>503</code> ("instance is not ready yet,  

returning unavailable") instead of the expected <code>200/403/500</code>.

<strong>Root cause.</strong> <code>GetOrStartInstance</code> is non-blocking, and the instance's  

health flag is set asynchronously via the plugin status listener  

(<code>instance-health-check</code>). Right after <code>Start()</code> returns, <code>Healthy()</code>  

can still be <code>false</code>, so the filter takes the not-ready path  

(<code>opaserveresponse.go</code>, <code>if !f.opa.Healthy()</code>). The test fired its  

request before the instance became healthy.

<strong>Approach.</strong> Wait for readiness before sending the request using  

<code>require.Eventually</code> on <code>inst.Started() &amp;&amp; inst.Healthy()</code>, mirroring  

the pattern already used in <code>openpolicyagent_routeupdate_test.go</code>. This  

only changes the test; the production behavior (returning 503 while  

not-ready is intentional) is unchanged.

<strong>Tests.</strong> <code>go test -run TestServerResponseFilter -count=20 ./filters/openpolicyagent/opaserveresponse/</code> is green; the full package,  

<code>go vet</code>, and <code>gofmt</code> are clean.
