Updates <code>github.com/redis/go-redis/v9</code> from 9.21.0 to 9.22.0
<details> <summary>Release notes</summary>

<em>Sourced from <a href="https://github.com/redis/go-redis/releases">github.com/redis/go-redis/v9's releases</a>.</em>
>
> 9.22.0
>
> This is a minor release introducing two flagship (experimental)
> features — <strong>client-side caching</strong> and <strong>automatic pipelining</strong> — alongside support for Redis 8.10, new commands,
> and a large batch of stability and parser-robustness fixes. It
> consolidates everything shipped in 9.22.0-beta.1, so the notes below
> cover the full 9.21.0 → 9.22.0 upgrade.
>
> :warning: Two changes to be aware of when upgrading from 9.21.0:
>
> * <strong>Default configuration values changed</strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3918">#3918</a>): read/write timeouts, retry backoff, cluster state reload interval, and TCP keep-alive defaults are now aligned with the cross-SDK configuration proposal (see the highlight below). Explicitly configured values are unaffected.
> * <strong><code>WaitAOF</code> return type corrected</strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3888">#3888</a>): <code>WaitAOF</code> now returns <code>*IntSliceCmd</code>, matching the two-integer reply of <code>WAITAOF</code> (previously <code>*IntCmd</code>, which failed to parse the reply at runtime). Code referencing the old return type needs a one-line update.
>
> 🚀 Highlights
>
> Client-Side Caching (Experimental)
>
> The standalone <code>Client</code> gains server-assisted client-side
> caching built on RESP3 <code>CLIENT TRACKING</code>. Enable it by
> setting <code>ClientSideCacheConfig</code> in <code>Options</code> (or
> supply your own cache via <code>ClientSideCache</code> — e.g. to share
> one cache across clients). Cacheable read results are served from a
> local in-process cache and invalidated automatically when the server
> reports a change, cutting round trips for read-heavy workloads.
>
> The invalidation architecture is selected by
> <code>ClientSideCacheStrategy</code>; the default (and currently only)
> strategy is <code>CSCStrategySharedTracking</code>: one shared cache,
> every pool connection runs plain <code>CLIENT TRACKING ON</code>, and a
> background drainer applies buffered invalidations — portable (no BCAST)
> and consistent with the other Redis client libraries. Requirements and
> guardrails: RESP3 (<code>Protocol: 3</code>), standalone client, DB 0
> only; commands that would change the connection identity
> (<code>SELECT</code>, <code>AUTH</code>, ...) are rejected while caching
> is enabled, and CSC is disabled when a credentials provider is set
> (fixed <code>Username</code>/<code>Password</code> work and are
> namespaced). See the README's <a href="https://github.com/redis/go-redis/blob/HEAD/README.md#client-side-caching">client-side caching section</a> and the runnable <a href="https://github.com/redis/go-redis/blob/HEAD/example/client-side-caching">example</a>.
>
> <strong>Experimental:</strong> the API may change in a minor
> release.
>
> (<a href="https://redirect.github.com/redis/go-redis/pull/3941">#3941</a>)
> by <a href="https://github.com/ofekshenawa"><code>@​ofekshenawa</code></a>
>
> Automatic Pipelining (Experimental)
>
> <code>AutoPipeliner</code> is a background batcher that coalesces
> commands from many concurrent goroutines into Redis pipelines,
> multiplying throughput without any manual pipeline management. It comes
> in two faces, available on <code>Client</code> and
> <code>ClusterClient</code> (and configurable via
> <code>Options.AutoPipelineOptions</code> /
> <code>UniversalOptions.AutoPipelineOptions</code>):
>
> * <strong><code>AutoPipeline()</code></strong> — the blocking face: a drop-in <code>Cmdable</code> where each call blocks until executed, exactly like a plain client, while concurrent callers' commands batch together under the hood (measured locally over loopback: ~1M+ SET/sec vs ~100k unpipelined; indicative, not a guarantee). Per-goroutine command order is preserved.
> * <strong><code>AsyncAutoPipeline()</code></strong> — the deferred face: command calls return immediately and every typed result accessor (<code>Val</code>/<code>Result</code>/<code>Err</code>/...) blocks until the command has executed. Submit a window of commands, then read the results, to keep pipelines deep (~2–3M SET/sec locally; indicative).
>
> <code>AutoPipelineOptions</code> controls batching:
> <code>MaxBatchSize</code> (soft target, default 200; the blocking face's
> preset uses 300), <code>MaxBatchBytes</code> (approximate payload cap so
> huge values flush as several bounded writes), <code>MaxFlushDelay</code>
> with optional <code>AdaptiveDelay</code> (delay scales down as the queue
> fills), and <code>MaxConcurrentBatches</code> (default 1 = a single
> ordered batch stream; raising it requires <code>Unordered: true</code>,
> so ordering is never lost by accident — <code>Validate()</code> rejects
> the combination otherwise). A usage tour and throughput comparison live
> in <a href="https://github.com/redis/go-redis/blob/HEAD/example/autopipeline"><code>https://github.com/redis/go-redis/blob/HEAD/example/autopipeline</code></a>.
>
> <strong>Experimental:</strong> the API may change in a future release
> — pin your go-redis version if you adopt it.
>
> (<a href="https://redirect.github.com/redis/go-redis/pull/3942">#3942</a>)
> by <a href="https://github.com/ndyakov"><code>@​ndyakov</code></a>, with
> help from <a href="https://github.com/cxljs"><code>@​cxljs</code></a>
>
> Redis 8.10 Support
>
> This release adds support for <strong>Redis 8.10</strong>. The
> README's supported-versions list now includes Redis 8.10, and CI runs
> the full suite against the
> <code>redislabs/client-libs-test:8.10.0</code> image by default (<a href="https://redirect.github.com/redis/go-redis/pull/3920">#3920</a>,
> <a href="https://redirect.github.com/redis/go-redis/pull/3940">#3940</a>).
>
> Coverage for the new commands and options that ship with Redis
> 8.10:
>
> * <strong><code>HIMPORT</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3919">#3919</a>) — bulk hash import via server-side fieldsets, exposed as <code>HImportPrepare</code>, <code>HImportSet</code>, <code>HImportDiscard</code>, and <code>HImportDiscardAll</code>. Fieldsets are session state scoped to a single physical connection, which does not mix well with connection pooling — so the client keeps a versioned fieldset registry and lazily replays the <code>PREPARE</code> on whichever pooled connection executes a <code>SET</code> that needs it, at most once per connection, with no extra round trip (the <code>PREPARE</code> is injected into the same write as the <code>SET</code>).
> * <strong><code>LMOVEM</code> / <code>BLMOVEM</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3913">#3913</a>) — move multiple elements between lists in one call.
> * <strong><code>SUNIONCARD</code> / <code>SDIFFCARD</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3897">#3897</a>) — cardinality of set union/difference without materializing the result.
> * <strong><code>XREAD</code> / <code>XREADGROUP</code> <code>MAXCOUNT</code> and <code>MAXSIZE</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3898">#3898</a>) — bound how much data a stream read returns.
> * <strong><code>TS.READ</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3896">#3896</a>), <strong><code>TS.QUERYLABELS</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3926">#3926</a>), <strong><code>TS.NRANGE</code> / <code>TS.NREVRANGE</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3870">#3870</a>) with multiple aggregators per key (<a href="https://redirect.github.com/redis/go-redis/pull/3937">#3937</a>), and <strong><code>EXCLUDEEMPTY</code></strong> on <code>TS.MRANGE</code> / <code>TS.MREVRANGE</code> (<a href="https://redirect.github.com/redis/go-redis/pull/3912">#3912</a>) — new time-series query surface.
> * <strong><code>FT.ALIASLIST</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3925">#3925</a>), <strong><code>COLLECT</code> reducer for <code>FT.AGGREGATE</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3886">#3886</a>), <strong><code>RERANK</code> on HNSW vector fields in <code>FT.CREATE</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3927">#3927</a>), and <strong><code>FT.HYBRID</code> timeout warnings</strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3911">#3911</a>) — search coverage.
>

> proposal shared by all Redis client libraries (<a href="https://redirect.github.com/redis/go-redis/pull/3918">#3918</a>):

> * <strong><code>XREAD</code> / <code>XREADGROUP</code> <code>MAXCOUNT</code> and <code>MAXSIZE</code></strong> (<a href="https://redirect.github.com/redis/go-redis/pull/3898">#3898</a>) — bound how much data a stream read returns.
