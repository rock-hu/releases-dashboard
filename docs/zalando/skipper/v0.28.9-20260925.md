Symptom

<code>dropRequestCookie</code> and <code>dropResponseCookie</code> remove cookies they were  

not asked to remove. Route:

    r: * -> dropRequestCookie("session") -> dropResponseCookie("session") -> "http://backend"

Request:

    Cookie: session=abc; consent={"ads":false}

Backend response:

    Set-Cookie: session=abc; Path=/
    Set-Cookie: consent={"ads":false}; Path=/; Priority=High

Through a skipper built from master, the backend prints  

<code>r.Header.Values("Cookie")</code> and the client prints  

<code>rsp.Header.Values("Set-Cookie")</code>:

    backend received Cookie: []
    client received Set-Cookie: []

The <code>consent</code> cookie is gone in both directions. Expected:

    backend received Cookie: ["consent={\"ads\":false}"]
    client received Set-Cookie: ["consent={\"ads\":false}; Path=/; Priority=High"]

Any cookie whose value contains a double quote, a backslash or a  

non-ASCII byte (<code>bar=José</code>, <code>bar=a\b</code>) disappears the same way. The  

cookies that do survive are rewritten:

* request values with a space or a comma get quoted: <code>bar=hello world</code>  
  becomes <code>bar="hello world"</code>, <code>bar=a,b</code> becomes <code>bar="a,b"</code>
* <code>Set-Cookie</code> attributes that <code>net/http</code> does not know are removed:  
  <code>bar=x; Path=/; Priority=High</code> becomes <code>bar=x; Path=/</code>
* an <code>Expires</code> that <code>net/http</code> cannot parse is removed
* attribute order and casing change: <code>bar=x; path=/; secure; httponly</code>  
  becomes <code>bar=x; Path=/; HttpOnly; Secure</code>

Both filters only promise to delete the given cookie.

Cause

<code>filters/cookie/cookie.go</code>:

    cookies := request.Cookies()
    ...
    request.Header.Del("Cookie")
    for _, c := range cookies {
    	if c.Name != name {
    		request.AddCookie(c)
    	}
    }

and the same with <code>rsp.Cookies()</code> / <code>Header.Add("Set-Cookie", c.String())</code> for the response.

<code>Request.Cookies</code> and <code>Response.Cookies</code> skip every cookie whose value  

has a byte outside RFC 6265 <code>cookie-octet</code>, so those cookies are missing  

from the list that is written back. <code>AddCookie</code> quotes values with  

spaces or commas, and <code>Cookie.String</code> writes only the attributes  

<code>net/http</code> knows and could parse.

Fix

Remove the matching cookie from the raw header values and leave the  

other cookies as they arrived. The cookie name is the text before the  

first <code>=</code> of a cookie pair (request) or of the first attribute  

(<code>Set-Cookie</code>), which is how <code>net/http</code> reads it too. A header without  

the cookie is not touched.
