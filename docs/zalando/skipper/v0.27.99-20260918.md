Root Cause

In <code>TestProxyListenerWithProxyClient/test_skip_list</code>, the listener is  

configured with <code>SkipListCIDRs</code>, which intentionally skips parsing the  

PROXY protocol header. When <code>createProxyClient</code> dials in, it immediately  

sends a binary PROXY v2 header directly into <code>http.Server</code>.  

Because the incoming bytes are not a valid HTTP request line,  

<code>http.Server</code> rejects them with <code>HTTP/1.1 400 Bad Request</code> and  

<code>Connection: close</code> before terminating the TCP connection. When using  

Go's standard <code>http.Client.Do</code> on a connection that is abruptly closed  

while client-side write/read synchronization is in flight, <code>net/http</code>  

hits a known transport race condition (ref: <a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="429405762" data-permission-text="Title is private" data-url="https://github.com/golang/go/issues/31259" data-hovercard-type="issue" data-hovercard-url="/golang/go/issues/31259/hovercard" href="https://github.com/golang/go/issues/31259">golang/go#31259</a>), returning  

<code>readLoopPeekFailLocked</code> and failing the test.

Changes

* Replaced <code>http.Client.Do</code> in <code>test_skip_list</code> with a direct TCP  
  exchange (<code>executeSkipListRequest</code>) using <code>http.ReadResponse</code>,  
  completely bypassing <code>http.Transport</code>'s background <code>readLoop</code> race on  
  early connection resets.
* Added <code>io.Copy(io.Discard, rsp.Body)</code> before closing response bodies  
  to properly drain remaining socket buffers.
* Added <code>defer client.CloseIdleConnections()</code> to prevent lingering idle  
  pooled connections from racing with server shutdown.
