decoding it. The decoder reads privately owned bytes after releasing the  

shard lock.

Changes

* Reuse the shard lookup and LRU promotion, borrowing bytes owned by the  
  entry store.
* Keep the defensive copy on the public byte-store API and decode fresh  
  payloads, headers and Vary metadata for each storage read.

The stored JSON representation, byte-based eviction, freshness windows  

and response selection are unchanged. Misses and L2 fetches are outside  

the optimization.

Testing

<a href="/zalando/skipper/blob/v0.28.62/filters/cache/filter_benchmark_test.go">BenchmarkCacheHit</a> measures  

complete serial warm-handler GETs with empty, 4 KiB and 64 KiB text  

bodies. It includes routing, decoding, default tracing, response writing  

and access-log formatting into a discard sink. Reproduce with <code>go test ./filters/cache -run '^$' -bench '^BenchmarkCacheHit$' -benchmem</code>.

These are in-process warm L1 measurements, not network latency or  

deployed traffic savings.

<code>TestShardedByteLRU_GetIsolation</code> checks defensive byte copies.  

<code>TestLRUStorage_GetIsolation</code> checks nested mutable results.  

<code>TestLRUStorage_SnapshotLifetime</code> checks retained bytes across  

overwrite, deletion, eviction and expiry;  

<code>TestLRUStorage_ConcurrentReads</code> exercises readers and writers under the  

race detector. Existing cache filter tests cover GET, HEAD, conditional  

304 and Vary results.

The Docker-backed <code>filters/cache.TestValkeyStorage_GetSetDelete</code> and  

<code>filters/cache.TestValkeyStorage_FallsBackToL1OnValkeyUnavailable</code>  

require a Docker daemon, which is unavailable here; they remain for  

target CI.
