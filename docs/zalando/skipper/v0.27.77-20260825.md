fix: deduplicate fifoWithBody and lifoWithBody in the route preprocessor (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5236222123" data-permission-text="Title is private" data-url="https://github.com/zalando/skipper/issues/4217" data-hovercard-type="pull_request" data-hovercard-url="/zalando/skipper/pull/4217/hovercard" href="https://github.com/zalando/skipper/pull/4217">#4217</a>)

<code>Registry.Do</code> keys the queue by route id, so <code>fifo()</code> and  

<code>fifoWithBody()</code> on the  

same route share one queue, same for <code>lifo()</code> and <code>lifoWithBody()</code>. The  

preprocessor drops all but the last instance to avoid that, but it only  

counted  

<code>filters.FifoName</code> and <code>filters.LifoName</code>, so the WithBody variants were  

never  

removed. Both then call <code>Wait()</code> on the same queue and one request takes  

two  

slots.

A single request to an idle proxy rejects itself:

    ./bin/skipper -inline-routes='r: * -> fifoWithBody(1, 0, "1s") -> fifoWithBody(1, 0, "1s") -> "http://127.0.0.1:9001"'

    curl -s -o /dev/null -w '%{http_code}\n' localhost:9090
    503

<code>lifoWithBody</code> twice blocks for the timeout and gives 502, and <code>fifo()</code>  

followed  

by <code>fifoWithBody()</code> gives 503 too. With <code>fifo()</code> twice it's 200, since  

that pair  

already gets deduplicated.

Counting per queue family instead of per filter name. <code>lifoGroup()</code>  

stays out of  

it, that one is keyed by group name.
