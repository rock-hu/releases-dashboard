fastcgi: do not pass client Proxy header as HTTP_PROXY (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="5982145769" data-permission-text="Title is private" data-url="https://github.com/zalando/skipper/issues/4367" data-hovercard-type="pull_request" data-hovercard-url="/zalando/skipper/pull/4367/hovercard" href="https://github.com/zalando/skipper/pull/4367">#4367</a>)

Regression test against master, <code>go test ./proxy/fastcgi -run TestFastCgiDropsProxyHeader</code>:

fastcgi_test.go:107: Proxy header passed to FastCGI application as  

HTTP_PROXY: "<a href="http://attacker.example:3128" rel="nofollow">http://attacker.example:3128</a>"  

--- FAIL: TestFastCgiDropsProxyHeader (0.00s)

Expected: a client supplied <code>Proxy</code> header never reaches the FastCGI  

application. Actual: <code>gofast.MapHeader</code> maps it to <code>HTTP_PROXY</code>, which  

PHP <code>getenv("HTTP_PROXY")</code> and CGI-unaware HTTP clients read as the  

outbound proxy, so any client can route the application's outgoing  

requests through a host it controls (httpoxy, <a title="CVE-2016-5385" data-hovercard-type="advisory" data-hovercard-url="/advisories/GHSA-m6ch-gg5f-wxx3/hovercard" href="https://github.com/advisories/GHSA-m6ch-gg5f-wxx3">CVE-2016-5385</a> class).  

<code>Proxy</code> is not in the proxy's hop header list, so nothing strips it  

earlier.

Fix: delete <code>HTTP_PROXY</code> in the existing param middleware in  

<code>NewRoundTripper</code>, next to the <code>REQUEST_SCHEME</code> cleanup. This matches  

what Go's <code>net/http/cgi</code>, nginx and Apache do. The test passes with the  

patch; <code>go vet</code> and <code>staticcheck</code> are clean for the package.
