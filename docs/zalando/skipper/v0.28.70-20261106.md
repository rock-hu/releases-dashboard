Add shared OpenID discovery cache for JWT and introspection (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="6167937822" data-permission-text="Title is private" data-url="https://github.com/zalando/skipper/issues/4400" data-hovercard-type="pull_request" data-hovercard-url="/zalando/skipper/pull/4400/hovercard" href="https://github.com/zalando/skipper/pull/4400">#4400</a>)

Introduce an opt-in, process-wide OpenID discovery cache shared by  

<code>jwtValidation</code> and all eight <code>oauthTokenintrospection*</code> filters.  

Disabled callers continue to fetch discovery on every filter creation,  

bypassing the cache and its global lock entirely.

When enabled, successful discovery documents are keyed by exact issuer  

URL. Cache hits during route creation send no HTTP request, so warm  

routing rebuilds can survive an issuer outage. Misses hold a global  

write lock through the HTTP request and JSON decode. Failures are not  

cached and there is no entry limit.

A shared hourly cleaner replaces the whole map on each tick. Library  

owners enabling the cache via <code>TokenintrospectionOptions</code> must acquire a  

cleaner with <code>StartOpenIDConfigCacheCleaner</code> and release it after  

routing teardown; Skipper's <code>run</code> acquires one automatically when  

<code>EnableOpenIDConfigCache</code> is set.
