Motivation

When querying the Kubernetes API server with pagination chunking  

enabled, requests can fail with HTTP status <code>410 Gone</code> if etcd compacts  

the resource version or the continue token expires mid-stream. Adding  

metric tracking for <code>410 Gone</code> provides immediate visibility into  

pagination expiration and compaction issues.  

Posted as  

<a href="https://github.com/zalando/skipper/pull/4321#discussion_r4322401467" data-hovercard-type="pull_request" data-hovercard-url="/zalando/skipper/pull/4321/hovercard">comment</a>

Summary

* Defined <code>errResourceGone</code> sentinel error in  
  <code>dataclients/kubernetes/clusterclient.go</code>.
* Added <code>Metrics</code> field to <code>kubernetes.Options</code> with graceful fallback  
  to <code>metrics.Default</code> and <code>metrics.Void</code>.
* Wired <code>Metrics</code> in <code>KubernetesDataClientOptions()</code> from Skipper's root  
  options.
* Intercepted <code>410 Gone</code> responses in <code>clusterClient.getJSON</code> and  
  incremented counter metric <code>k8s.gone</code>.
* Added unit tests in <code>dataclients/kubernetes/clusterclient_test.go</code>  
  using <code>metricstest.MockMetrics</code>.
